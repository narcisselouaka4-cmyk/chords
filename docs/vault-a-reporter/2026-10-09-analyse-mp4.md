# Analyse — MP4 accepté, plus de « type de vidéo », accords justes pour les morceaux du Studio (09/10/2026)

À reporter dans le vault :
- `log.md`, `state/current-work.md` ;
- `decisions/` : l'onglet Analyse accepte le MP4 et ne demande plus le type de vidéo ; l'analyse
  n'utilise les pistes séparées du Studio que si elles couvrent tout le morceau ;
- `features/analyse-definition-of-done.md` : formats acceptés MP3, WAV, M4A, **MP4** ;
- `state/next-actions.md` : les vérifications en bas.

## Ses demandes
« Dans l'onglet Analyse, les fichiers MP4 ne sont pas autorisés. Comme la bibliothèque du Studio
et celle d'Analyse sont reliées, quand je choisis un MP4 dans la bibliothèque, l'analyse ne
fonctionne pas : aucun accord affiché, rien du tout. »
1. Ajouter le MP4 dans l'onglet Analyse.
2. Supprimer l'étape qui demande quel type de vidéo a été importé.
3. Faire en sorte qu'il y ait bien les accords.

## Causes
- **Import** : le sélecteur de l'Analyse (`studio:select-audio-file`) ne proposait que MP3, WAV,
  M4A (la carte « Vidéo (MP4) » avait été retirée à la refonte du 02/10).
- **Type de vidéo** : un MP4 (y compris venu de la bibliothèque) passait par l'état `video-type`
  (« Quel type de vidéo avez-vous importé ? » : tutoriel, cover, morceau, démo). Le choix n'était
  qu'enregistré dans l'analyse (`videoType`), il ne changeait rien au calcul.
- **Aucun accord** : `runAnalysisPipeline` (`electron/main.js`) prenait d'office le piano et la
  basse séparés dans le Studio pour ce fichier, s'ils existaient. Or ces pistes :
  - ne couvrent que la **région** travaillée (5 min au plus), leurs temps partant du début de la
    région — pas du morceau ;
  - peuvent être des **bips de 2 s** (Demucs absent, ou anciens échecs non marqués, voir
    `2026-10-09-studio-separation-bips.md`).
  Ses MP4 de la bibliothèque sont justement passés par le Studio : l'analyse travaillait sur des
  bips ou sur un extrait décalé.
  - Non établi pour un morceau précis : lequel des deux cas, faute d'accès à ses fichiers ; les
    deux mènent au même symptôme.

## Fait
- `electron/main.js` :
  - `studio:select-analysis-file` : MP3, WAV, M4A, MP4 ;
  - `findStudioStemForFile(filePath, stem, duration)` remplace les deux fonctions piano/basse :
    pistes écartées si bips (marque `simulated.json` ou anciens bips) ou si la région
    (`metadata.json`) ne couvre pas tout le morceau (tolérance 0,5 s) → analyse sur le mix ;
  - la durée du fichier est lue **avant** de choisir les pistes.
- `preload.{cjs,js}`, `media-engine.js` : `selectAnalysisFile()`.
- `analyzer-tab.js` : un seul import (audio ou MP4), même écran de préparation pour les deux
  (icône 🎬 pour une vidéo), état `video-type` et son code retirés.
- `analyzer-workflow.js` : états `import`, `prepare`, `analysis` ; `resolveAnalysisState` →
  toujours `prepare`.
- `index.html` : écran du type de vidéo retiré ; accueil « Choisir un fichier audio ou vidéo —
  MP3, WAV, M4A ou MP4 » ; « Préparer l'analyse ». CSS de l'écran retiré.
- Les analyses déjà enregistrées avec un `videoType` se rouvrent toujours (champ conservé).

## Vérifié
- Un vrai MP4 (vidéo H.264 + son AAC, accords de synthèse) : extraction par `audio-processor.py
  extract`, puis `analyze-chords` → tonalité Do, grille avec temps (Am F G…). Le Do initial lu
  comme Am vient du moteur sur ces sons de synthèse (même résultat sur le WAV d'origine), pas du
  MP4.
- Règle des pistes du Studio, sur un faux dossier Studio : anciens bips → mix ; bips marqués →
  mix ; région 120–420 s sur 467 s → mix ; région 0–300 s sur 467 s → mix ; région = morceau
  entier → piste piano.
- `test-analysis-workflow.js` (réécrit pour le MP4 et les pistes), `test-analysis-dom.js`,
  `test-analysis-persistence.js`, `test-studio-dom.js`, build, régressions Partie 1 et Partie 3.

## Ajout — clic sur une étiquette d'accord, mini-clavier de « Accord à l'écoute »
**Ses demandes** : 1) un clic gauche sur une étiquette d'accord ramène la lecture à cet accord ;
2) améliorer la carte « Accord à l'écoute » : « le mini keyboard est totalement cassé ».

- **1 — Fait** (`analyzer-tab.js`, `seekToSegment`) : clic sur une étiquette de la frise (et sur
  une pastille du parcours dans « Vue d'ensemble ») → la lecture se place au début de l'accord ;
  en lecture elle continue de là, en pause elle y reste ; curseur, frise et carte suivent.
  L'heure est écrite directement sur l'élément audio : `seek()` du lecteur borne par
  `audio.duration`, qui vaut NaN avant la lecture des métadonnées (retour à 0).
- **2 — Cause** (`mini-keyboard.js`) : les dégradés des touches avaient les mêmes `id` dans tous
  les mini-claviers de la page. `url(#id)` désigne le PREMIER élément de ce nom dans le
  document ; dès le chargement, ce premier mini-clavier est dans un panneau caché, et Chromium
  ne peint pas un dégradé posé dans un sous-arbre `display:none` → touches noires vides, notes
  jouées sans couleur, partout où un mini-clavier s'affiche (pas seulement en Analyse).
  Mesuré dans la page : une seule définition `mk-off-b`, dans un SVG de largeur 0.
- **2 — Fait** : un suffixe unique par SVG pour ses dégradés. Et dans la carte : le clavier
  prenait toute la largeur (≈ 720 px, plus de 200 px de haut) et sortait de la carte → borné à
  440 × 132 px, centré, ombre douce (`astra-bridge.css`).
- **Vérifié** dans Chromium (application complète, fausse couche Electron, analyse C Am F G7…,
  vrai fichier son) : clic sur « G7 » (10–12 s) → lecture à 10 s, carte « G7 — D·F·G·B » ;
  captures en sombre et en clair : touches noires pleines, quatre notes colorées, clavier
  entier dans la carte. `test-analysis-dom.js` : deux contrôles de plus (dégradés propres à
  chaque SVG ; clic → lecture). Pédagogie 177/177, Copilote 37/37, build, Parties 1 et 3.
- **À vérifier sur sa machine** : cliquer plusieurs étiquettes en lecture et à l'arrêt ; la
  carte « Accord à l'écoute » et les autres mini-claviers (Entraînement, Pédagogie).
